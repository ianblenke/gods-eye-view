Two runs of the layer in a real browser, with a fake upstream behind the real routes of change 3.
The runs used the files of the commit c53f05d9. The layer files of the commit 68267375 are the same: the command git diff --stat c53f05d9 68267375 -- src server build ':(exclude)*.test.mjs' prints nothing.
Browser: Google Chrome 147.0.7727.101, headless, software rendering. Server: the Vite dev server of the repository on 127.0.0.1:5199, run by host Node.
The server has three plugins. These are a counter of requests to the four routes, the real plugin beemapsBurstProxy of change 3, and the not-found plugin of the API.
The plugin got a fake fetch function. The fake answers the create request with one made-up burst, and the list request with the bursts that it made. A mode can make it slow or make it fail with the status 500.
The fake records the URL, the header Authorization and the box of each create request. No request left the machine, because the plugin has only the fake fetch function. The key is a made-up fixture text. The budget file and the audit file live in temporary folders.
The scripts (the driver and the Vite config) are not in the repository. They live in the tools folder of the lead, because a script in a change folder is a coverage gap.
The page loads the share link as the hash #v=2&lat=60&lon=10&alt=3000&heading=0&pitch=-90&roll=0&l=6. The first-run chooser is suppressed through localStorage before the page loads.
The driver clicks with real mouse events of the DevTools protocol at the position of each control. The data panel is opened with its own button.
The driver loads the page once and waits 45 seconds before the checks, as a precaution against a cold cache of Vite. The warm-up load waits up to 300 seconds for the row.
The panel and the page are slow with software rendering. Row texts can come 3 to 11 seconds after the answer of a route. So the driver waits for each expected text.
The step 4 presses "Quote burst here" twice in a row. A script in the page watches the Confirm chip with a MutationObserver. It records when the chip first shows disabled and when it becomes enabled.
The lower bound is the wall clock time of the answer of the quote route plus 1000 milliseconds. The layer starts its wait after it reads the answer, so the chip cannot be enabled earlier.
The tint checks take a screenshot and compute the mean color of the middle of the globe. A box of the quote shifts it toward amber, and a box of a created burst shifts it toward blue.
The app renders on demand. An earlier run of this driver found a quote box that stayed invisible, because the layer did not ask for a frame.
The layer now asks for one frame after each change of the boxes. The commit c53f05d9 is the first commit with this change.
The first attempts of the driver stopped at checks or waits. Each cause was in the driver or in the fake:
- The fake upstream read the create body as an object, and the plugin sends an array. The layer then showed the warning for an unclear answer, as it must.
- The server limits confirm requests to 3 for each minute, and the driver sent 4 too fast. The driver now waits for the window.
- A fixed sleep came before the row had its new text. The driver now waits for the text.
- The second of two runs in a row stopped at step 1, because the row did not show within 120 seconds. The warm-up load now waits up to 300 seconds, and the Vite log of the later runs has no line about a reload.
- The first lock check measured from the moment of the first sight of the chip, and not from the answer of the quote.

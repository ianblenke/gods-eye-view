Equivalent faults. The description is first and the reason follows:
- "Round the snapped centre to 4 decimals". The snapped value is a multiple of 0.001 or 0.005 plus a float error near 1e-14, so 3 or 4 decimals give the same number
- "Read the height of the canvas without the optional chain". The first operand is true for an undefined canvas, so the second operand never runs with an undefined canvas
- "Return undefined in place of null for a canvas with no size". The press passes the result to framesBox, which reads centre?.lat and centre?.lon, so undefined and null both give the reason sky
- "Set hit to null in the catch in place of returning null". The next line, if (!hit) return null, returns null for a hit that is null, so the result of viewCentre is the same
- "Write a credit field with a template in place of String". For a number, the template literal and String() give the same text, and the test of the value is the same
- "Report the status after the body is read". readDocument never throws. Only the plugin reads the seen record, after callUpstream returns, so the order of the two steps cannot show.
- "Report the status twice when the headers arrive". The observer copies the same value into the seen record twice, so the second call changes nothing
- "Reset the status to none when the call fails". The catch runs only when fetchImpl throws, before the status is observed. So the status is none already. readDocument and failureOf never throw for a real Response.
- "Report the size of the body twice". The observer copies the same value into the seen record twice, so the second call changes nothing
- "Test the credit limit text for a number above 0". After the digits-only test the number is a whole number, so above 0 and 1 or more are the same test.
- "Accept an empty text in the digits test of the credit limit". An empty text gives Number("") = 0, and the test for 1 or more refuses it, so the limit is the default as before.
- "Accept a minus sign in the credit limit text". A text with a minus sign gives a number below 1 (also "-0" gives -0), and the test for 1 or more refuses it.
- "Read the credit limit with parseInt in place of Number". The text has digits only here, and for such a text parseInt in base 10 and Number give the same number.
- "Accept 0 in the test of the added credits". The forms differ only for the input -0: the fault gives -0 and the code gives 0. The only caller adds an amount only when it is above 0, which -0 is not.
- "Give a missing credit file an empty date". check() calls roll() at once after the load, and roll replaces a state of another date with today and 0.
- "Read the credit file without the encoding". JSON.parse of a Buffer converts it with toString, which reads UTF-8, so the parsed value is the same.
- "Read the credit file date without the optional chain". A null saved value then throws a TypeError, which check() catches like the Error of the line below, so the answer is unavailable as before.
- "Change the text of the error for a credit file that is not usable". check() catches each error of load() and ignores the message, so the text is never read.
- "Load the whole object of the credit file as the state". The state holds the same date and used, roll() makes new states with two keys, and add() writes only date and used.
- "Write the credit file without the encoding". A string is written as UTF-8 by default, so the bytes of the file are the same.
- "Test the credit addition by the truth of the amount". creditsOf gives 0 or a finite number above 0, so the amount is true exactly when it is above 0.
- "Add creditsUsed of the document in place of the amount". The call runs only when added is above 0, and then creditsOf gave document.creditsUsed itself.
- "Swap the order of the used and limit keys of the credit_budget answer". The text of the answer changes, but the parsed object is the same, and the tests and the layer read the answer as parsed JSON
- "Compare the whole credits of the count with the limit". The limit is always a whole number: digits only, or 500. For a whole n, floor(x) >= n is the same as x >= n.
- "Test the loaded state with a falsy test". The state is null or an object, so !state and state === null give the same result
- "Give a missing file an empty date". The check calls roll() right after the load, and roll replaces a date that is not today with a new count of 0
- "Read the credit file as a buffer in place of UTF-8 text". JSON.parse turns the Buffer into text with the UTF-8 decoder of Buffer.toString, the same text
- "Read the saved object without the optional chain". JSON null makes saved.date throw a TypeError in load, and the catch of check gives the same unavailable result

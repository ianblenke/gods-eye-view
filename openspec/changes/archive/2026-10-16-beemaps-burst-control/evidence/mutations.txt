Runner: 6 scratch copies of the clone run in parallel. Each copy uses the same long-lived container of the image gods-eye-view:local, with the node_modules of the image.
Each fault runs first against the test file of its own file. The command is: timeout 100 node --test --test-concurrency=4 --test-timeout=6000 --test-reporter=spec <test file>
A fault that leaves that test file green then runs against all eight test files src/data/beemapsBurst*.test.mjs. The second step can only add failing tests. So a fault that fails no test in both steps is a real survivor.
The scenario in the first column is the scenario of a test that failed. The exceptions are the equivalent faults, which fail no test, and the faults in the list further below.
The container ran next to the two containers of the owner and stopped when the run ended. No other container ran at the same time.

The first attempt of run B was stopped and left no log. The survivors of the runs A to E led to these changes:
- A defect in the code: a ring of more than about 125000 positions made the list fail, because the code spread the positions into Math.min. The code now uses a reduce.
- A defect in the code: the ledger kept stray fields of a record when it changed its state. The ledger now replaces the record by a clean copy.
- A limit that no test could reach: the area compared a float with 0.1 and 5. The plugin now compares the area rounded to 3 decimals, and the spec says so.
- Checks that did the same work twice were removed. Examples are a type test before Number.isFinite, an if around a Math.max, and a test for null after the body read.
- Tests were added for each edge of a limit and each pattern of a key. Other tests pin the order of writes, the copy of a record, the headers of an answer and the defaults of the plugin.
- A false equivalent claim was found and removed. A date that is a list passes the pattern test, so the type test of the date is a real fault.
- The plugin now answers 500 with internal_error for an error that nobody expects. It writes no audit line for a request over the rate limit. It tries a blocked line after a failed first line.
- Each reason of an equivalent fault comes from a reading of the code. For the loop of the rate limiter, the script limiter-check.mjs also compared 1200000 decisions and found no difference.
- Run F was two runs of 1167 faults on the commit 74fe7431, before the formal review. Every fault that left the tests green was an equivalent fault.
Round 1 of the formal review found gaps in the tests and the faults. Each gap got a test and a fault, and the runs of this file ran after the corrections:
- Tests for the blocked line of busy, key_reused, the hold after an unknown outcome, budget_unavailable and ledger_unavailable. Nine faults answer at one site without a line.
- Tests that use up the quote after created, 400, budget_used, log_failed, budget_unavailable and a failed write of the pending record. Five faults give the quote back.
- Faults for the leak paths of scenario 032: the key in an answer, a header, a record, a line and the console. Others copy the text of a failed call, the body of a refusal and fields of Bee Maps.
- A test for the hold after an unknown outcome before the check of the quote, and faults for the order of three steps.
- Text corrections: the hold rule applies to a new key, the refusal sources apply to the create call, and two Known limits were added. The wording of the STE review was corrected.
Round 2 of the formal review found errors in the spec text and gaps in the faults:
- The spec now says that a hold answers before the quote, and that a repeat of a key has the quoteId of its record. The design now says that the record keeps its state after an error that nobody expects.
- Four faults were added. Three read the body before the check of the local request, one for each route. One moves the hold after a refusal before the replay of a record.
- Three test titles changed, and no test changed otherwise. The runs of this file ran after that change.

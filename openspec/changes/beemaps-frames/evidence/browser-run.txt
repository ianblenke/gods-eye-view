Run of the layer in a real browser, with a fake upstream behind the real route of change 1.
The run used the files of the commit 6c6fb1bd. The layer files of the commit 6dd67760 are the same: the command git diff --stat 6c6fb1bd 6dd67760 -- src server build ':(exclude)*.test.mjs' prints nothing.
Browser: Google Chrome 147.0.7727.101, headless, software rendering. Server: the Vite dev server of the repository on 127.0.0.1:5199, run by host Node. It has only three plugins. These are a counter of requests to the two routes, the real plugin beemapsProxy of change 1, and the not-found plugin of the API.
The plugin beemapsProxy got a fake fetch function. It answers every request for the one fixed address of Bee Maps with 6 made-up frames, and it throws no other address. No request left the machine. The key is a made-up fixture text. The budget file lives in a temporary folder.
The scripts (the driver and the Vite config) are not in the repository. They live in the tools folder of the lead, because a script in a change folder is a coverage gap. The page loads the share link as the hash #v=2&lat=60&lon=10&alt=3000&heading=0&pitch=-90&roll=0&l=5. The first-run chooser is suppressed through localStorage before the page loads.
The driver clicks with real mouse events of the DevTools protocol at the position of each control. The data panel is opened with its own button. The retry of a toggle click is counted in the lines below.
The fake upstream takes 20 seconds in the steps with the word slow, so that the state of a request in flight can be read.
This is the run that passed. Earlier runs of the same driver stopped at a check or at a wait. Each cause was in the driver. The share link needs lat and lon in the hash. The data panel starts closed. A click used a position that had moved. A check ran before the page had loaded again. No earlier run stopped because of the layer.
Vite is up on 127.0.0.1:5199
